PROMPT 1 (Inicial - Especificación completa)
----------------------------------------------------------------------------
El usuario solicitó construir un sistema completo de chatbot para WhatsApp
Business Cloud API con:
- 3 modos configurables: BOT (flujos), IA (LLM), HUMANO (agentes)
- Panel de administración web
- Stack: Node.js + Express + SQLite + React/HTML+Tailwind+Alpine.js + Socket.io
- 6 módulos: Configuración, Webhook, Orquestador, Flujos, Handoff, Contactos/Métricas
- Cliente IA genérico OpenAI-compatible (baseURL configurable)
- Cifrado AES de credenciales, JWT con roles, rate limiting
- Instrucción de esperar confirmación entre módulos

RESULTADO:
- Esquema de base de datos creado (10 tablas con relaciones)
- Estructura de carpetas completa (backend/src + public)
- Módulo 1 (Panel de configuración) implementado y verificado:
  - Pestaña WhatsApp: credenciales, App Secret, probar conexión
  - Pestaña IA: interruptor global, modos, parámetros, probar conexión
  - Pestaña Bot: flujos, palabras clave, menús
- Cifrado AES-256-GCM verificado (tokens no aparecen en plaintext en BD)
- Nota técnica: Node v24 no tiene prebuilds de better-sqlite3, se usó
  el módulo integrado node:sqlite (API compatible, sin compilación nativa)

Se construyeron los módulos 2 al 6 + README:

SECCIÓN 2: PROBLEMAS ENCONTRADOS Y RESUELTOS
================================================================================

----------------------------------------------------------------------------
PROBLEMA 1: better-sqlite3 no compila en Node v24
----------------------------------------------------------------------------
SÍNTOMA: npm install falla al compilar better-sqlite3 (no hay prebuilds
         para Node v24.18.0)
CAUSA:   Node v24 es muy nuevo, better-sqlite3 no tiene binarios precompilados
SOLUCIÓN: Se usó el módulo integrado node:sqlite (disponible en Node 22+)
         - API compatible (prepare/run/get/all)
         - Sin compilación nativa
         - Única diferencia: db.pragma() → db.exec('PRAGMA ...')
IMPACTO: Se actualizó database.js y package.json (engines >=22)

----------------------------------------------------------------------------
PROBLEMA 2: require('../models/contactos') no encontrado
----------------------------------------------------------------------------
SÍNTOMA: El servidor crashea al arrancar: "Cannot find module
         '../models/contactos'"
CAUSA:   El archivo se llama contacto.js (singular) pero se requirió
         como contactos (plural) en handoffService.js
SOLUCIÓN: Se corrigió el require a '../models/contacto'

----------------------------------------------------------------------------
PROBLEMA 3: Menú "Opciones" no se despliega
----------------------------------------------------------------------------
SÍNTOMA: Al hacer clic en "Opciones ▾" el menú no aparece
CAUSA:   @click.outside en el dropdown se disparaba inmediatamente con el
         mismo evento de clic del botón (el clic llega al document level
         y cierra el menú que apenas se abrió)
SOLUCIÓN: Se añadió @click.stop al botón para evitar que el evento
         propague al document level donde @click.outside escucha

----------------------------------------------------------------------------
PROBLEMA 4: Mensaje de WhatsApp no se refleja en el panel
----------------------------------------------------------------------------
SÍNTOMA: El usuario envía un mensaje desde su WhatsApp personal pero no
         aparece en el módulo "Agentes"
DIAGNÓSTICO EN CADENA:

  4a. Firma X-Hub-Signature-256 inválida
      ─────────────────────────────────
      SÍNTOMA: Log: "Webhook: firma X-Hub-Signature-256 invalida"
      CAUSA:   El App Secret guardado en BD era "test-secret-999" (de
               pruebas de desarrollo), no el real de la app de Meta
      SOLUCIÓN: Se limpió el App Secret (NULL) para desactivar la
               verificación de firma temporalmente

  4b. ngrok no estaba corriendo
      ─────────────────────────────────
      SÍNTOMA: Meta no puede alcanzar el servidor (no hay URL pública)
      CAUSA:   ngrok no estaba activo; public_url en BD era un placeholder
               ("https://demo.ngrok-free.app")
      SOLUCIÓN: Se inició ngrok http 3000
               URL obtenida: https://grain-borax-turban.ngrok-free.dev
               Se actualizó la BD y se verificó el webhook desde internet

  4c. La app no estaba suscrita a webhook events
      ─────────────────────────────────
      SÍNTOMA: Webhook verificado (Meta envió GETs de verificación y
               recibió 200) pero NO enviaba POSTs con mensajes
      CAUSA:   Aunque el usuario hizo "Verify and Save" en Meta, la app
               no estaba suscrita al campo "messages" a nivel de API
               (GET /{waba_id}/subscribed_apps devolvió vacío)
      SOLUCIÓN: Se suscribió programáticamente:
               POST /{waba_id}/subscribed_apps
               Body: {"subscribed_fields":["messages"]}
               Resultado: success: True

  RESULTADO FINAL: Tras la suscripción, se envió un mensaje al usuario,
  este respondió "Recibido", y el mensaje llegó al webhook:
  - Contacto creado: Gustavo (wa_id: 5212463118068)
  - Conversación creada: id=6, modo=bot
  - Bot respondió automáticamente con mensaje de bienvenida
